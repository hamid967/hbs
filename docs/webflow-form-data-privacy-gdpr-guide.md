# دليل أمان وحماية بيانات نموذج Webflow

**إعداد:** Manus AI  
**الغرض:** وضع ضوابط عملية لنموذج «اطلب عرضاً» أو نماذج التسويق في Webflow، مع مراعاة مبادئ GDPR وحماية البيانات.

> **تنبيه قانوني:** هذا الدليل تشغيلي وتقني، وليس استشارة قانونية أو تأكيداً بأن الموقع «متوافق مع GDPR». ينبغي أن يراجع مستشار قانوني مختص أساس المعالجة، نص الخصوصية، مدد الاحتفاظ، ونقل البيانات وفق الأسواق الفعلية للموقع.

## المبدأ الحاكم

تؤكد المفوضية الأوروبية مبادئ المشروعية والإنصاف والشفافية، وتحديد الغرض، وتقليل البيانات، وتحديد مدة الاحتفاظ، والنزاهة والسرية، والمساءلة؛ كما تشير إلى الحماية بالتصميم والافتراض. [1] لذلك يجمع النموذج فقط ما يحتاجه لطلب العرض، ويشرح سبب الجمع، ولا يستخدم البيانات لغرض تسويقي إضافي بلا أساس مناسب أو موافقة منفصلة عند الحاجة.

> «If you're creating forms that request personal data in Webflow, make sure to clearly ask for and get consent, unless another lawful basis for processing applies.» — Webflow Help Center [2]

## 1. خريطة البيانات والحد الأدنى من الحقول

| البيانات | هل تُجمع افتراضياً؟ | الغرض المحدد | الحقل مطلوب؟ | مدة الاحتفاظ المقترحة* | ملاحظة أمان |
|---|---|---|---|---|---|
| الاسم | نعم | مخاطبة مقدم الطلب ومتابعة العرض | نعم | 90 يوماً إن لم تتحول الفرصة إلى علاقة تجارية | لا تُطلب بيانات هوية رسمية |
| بريد العمل | نعم | الرد وتحديد سياق الشركة | نعم | 90 يوماً أو حسب سياسة المبيعات المعتمدة | تحقق من الصيغة ولا تستخدمه في URL |
| اسم الشركة | نعم | تخصيص العرض | نعم | 90 يوماً | لا تطلب سجلات شركات حساسة |
| حجم الشركة/الاهتمام | اختياري | توجيه الطلب للفريق المناسب | لا | 90 يوماً | استخدم قوائم محدودة القيم |
| رسالة مختصرة | اختياري | فهم الاحتياج | لا | 30–90 يوماً | نبّه المستخدم ألا يشارك بيانات موظفين أو معلومات حساسة |
| موافقة تسويقية | فقط عند الحاجة | رسائل تسويقية مستقبلية | لا | حتى سحب الموافقة أو مدة سياسة التسويق | منفصلة وغير محددة مسبقاً |
| ملفات مرفقة | لا افتراضياً | — | لا | — | تظل معطلة في الإصدار الأول لتقليل المخاطر |

\*المدد أمثلة تشغيلية يجب اعتمادها قانونياً وتوثيقها في سياسة الاحتفاظ.

## 2. تصميم النموذج والشفافية والموافقة

| الضابط | التنفيذ في Webflow | معيار القبول |
|---|---|---|
| إشعار قصير | أسفل زر الإرسال: الغرض، رابط سياسة الخصوصية، ووسيلة التواصل | مرئي قبل الإرسال ومقروء على الهاتف |
| موافقة التسويق | Checkbox اختياري منفصل عن طلب العرض | غير محدد مسبقاً ولا يمنع إرسال طلب العرض |
| منع البيانات الزائدة | عدم إضافة رقم هوية أو راتب أو بيانات صحية أو ملف مرفق | مراجعة الحقول قبل كل نشر |
| تثبيت الغرض | إظهار أن البيانات تستخدم للرد على طلب العرض فقط | يتطابق النص مع سجل المعالجة |
| تحذير الرسالة الحرة | نص مساعد يطلب عدم إدخال بيانات موظفين أو أسرار تشغيلية | ظاهر قرب حقل الرسالة |
| سياسة الخصوصية | رابط مباشر إلى سياسة محدثة بالعربية والإنجليزية عند الحاجة | يفتح ويعمل ولا يعيد 404 |

## 3. إشعار الخصوصية المطلوب قرب النموذج

يجب أن تشرح سياسة الخصوصية وإشعار النموذج، بلغة موجزة وواضحة، هوية المتحكم بالبيانات ووسيلة التواصل، وما البيانات التي تجمع، والغرض والأساس القانوني، والمستلمين أو فئاتهم، والنقل الدولي عند انطباقه، ومدة الاحتفاظ أو معيارها، وحقوق صاحب البيانات، وكيفية سحب الموافقة أو تقديم طلب. تدعم مراجع المفوضية الأوروبية هذه الشفافية وتحديد الغرض وتقليل البيانات. [1]

## 4. الوصول والتخزين والتكاملات

| المجال | الضابط المطلوب | دليل التحقق |
|---|---|---|
| Webflow Workspace | أقل عدد ممكن من المحررين، أدوار محددة، ومراجعة شهرية للوصول | قائمة مستخدمين ومالك لكل دور |
| إرسالات النموذج | تسمية نموذج مميزة، مستلمون بالاسم، ومراجعة إعدادات Forms | لقطة إعداد المستلمين واختبار إرسال |
| البريد | لا تُرسل كل بيانات النموذج إلى قوائم واسعة أو بريد مشترك غير محكوم | قائمة مستلمين معتمدة |
| CRM وWebhook | قائمة بكل وجهة، غرضها، مالكها، بياناتها المنقولة وDPA الخاص بها | سجل تكاملات ومراجعة ربع سنوية |
| الأسرار | لا مفاتيح API أو Tokens داخل Embed أو JavaScript عام | مراجعة الكود المخصص قبل النشر |
| السجلات | لا تُطبع حقول النموذج كاملة في سجلات المتصفح أو التحليلات | اختبار DevTools وخدمة التحليلات |
| النسخ والتصدير | تصدير الإرسالات محكوم بمالك وموقع تخزين ومدة حذف | سجل تصدير ومكان تخزين معتمد |

توضح وثائق Webflow أن إرسالات Forms يمكن إدارتها وتصديرها وحذفها من إعدادات الموقع، وأن حذف الإرسال يحذف الملفات المرتبطة به إن وجدت. [2] لذلك يحدد الفريق مالكاً واضحاً للحذف الدوري، ولا يعتمد على «ترك البيانات إلى الأبد» داخل Webflow أو CRM.

## 5. الموردون ونقل البيانات

توفر Webflow اتفاقية معالجة بيانات تتناول علاقة الأطراف، والمعالجات الفرعية، والتدقيق، ونقل البيانات خارج EEA/UK/Switzerland، والالتزامات بعد انتهاء العلاقة. [3] قبل ربط النموذج بـCRM أو أداة تسويق أو Webhook، يسجل الفريق المورد، ونوع البيانات، والغرض، وموقع النقل، وDPA أو شروط المعالجة، ومالك القرار.

| سؤال المراجعة | لا يبدأ التكامل قبل الإجابة |
|---|---|
| ما الغرض الدقيق من استقبال المورد للبيانات؟ | [الغرض] |
| ما الحقول التي تصل إليه؟ | [قائمة حقول دنيا] |
| من يملك المورد ويستجيب لطلبات الحذف؟ | [الدور والاسم] |
| هل توجد اتفاقية معالجة أو بنود نقل مناسبة؟ | [الرابط/القرار] |
| كيف يوقف الفريق التكامل ويعالج الإرسالات الفاشلة؟ | [خطة تراجع] |

## 6. الاحتفاظ والحذف وحقوق أصحاب البيانات

| العملية | الإجراء | المالك | زمن الاستجابة الداخلي |
|---|---|---|---|
| طلب وصول أو تصحيح | التحقق من الطلب، البحث في Webflow وCRM والبريد، وتسجيل النتيجة | مسؤول الخصوصية | وفق السياسة المعتمدة والقانون المطبق |
| طلب حذف | حذف أو تقييد الإرسال في Webflow وCRM ووجهات النسخ المصرح بها، مع سجل إثبات | مسؤول الخصوصية + مالك CRM | وفق السياسة المعتمدة والقانون المطبق |
| انتهاء مدة الاحتفاظ | مراجعة الإرسالات غير المؤهلة وحذفها وفق الجدول | مالك المبيعات | شهرياً |
| سحب موافقة التسويق | إزالة التصنيف التسويقي مع بقاء معالجة طلب العرض فقط عند وجود أساس مناسب | التسويق | فوري تشغيلياً |
| تغيير نموذج أو حقل | مراجعة غرض الحقل والاحتفاظ والسياسة قبل النشر | المنتج + الخصوصية | قبل النشر |

## 7. قائمة فحص أمنية قبل النشر

| الاختبار | معيار النجاح | أولوية الإطلاق |
|---|---|---|
| حقول النموذج | تجمع الحد الأدنى فقط ولا تقبل بيانات حساسة افتراضياً | P1 |
| الموافقة | اختيار التسويق منفصل وغير محدد مسبقاً | P1 |
| روابط الخصوصية | تعمل على الهاتف وسطح المكتب وتطابق الإشعار | P1 |
| Spam والحماية | اختبار مدخلات غير صالحة وتكرار الإرسال وحماية مناسبة | P1 |
| الوجهة | طلب اختبار يصل إلى وجهة معتمدة مرة واحدة فقط | P1 |
| الإشعارات | المستلمون مخولون ولا تحتوي الرسالة على حقول غير لازمة | P1 |
| الكود المخصص | لا أسرار أو بيانات نموذج في console أو tags غير معتمدة | P1 |
| التحليلات | لا ترسل البريد أو الرسالة الحرة كخصائص حدث | P1 |
| الحذف | اختبار حذف تجريبي في Webflow والوجهة المتكاملة | P2 |
| سجل التغيير | مالك وقرار ودليل لكل تعديل في الحقول أو التكامل | P2 |

## 8. الاستجابة للحوادث

عند الاشتباه في كشف بيانات أو إرسالها إلى وجهة غير معتمدة، يوقف الفريق النموذج أو التكامل المتأثر، ويحفظ الأدلة دون إعادة نشر أو حذف غير منضبط، ويحدد نطاق البيانات والأشخاص والوجهات، ثم يصعد الحادث إلى مالك الخصوصية والأمن والمستشار القانوني لتقرير واجبات الإخطار وفق القانون المطبق. لا يفترض الفريق أن حذف الخطأ من الواجهة يلغي النسخ التي وصلت إلى CRM أو البريد أو الأداة الخارجية.
