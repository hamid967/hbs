# أدوات وخدمات إدارة موافقة ملفات تعريف الارتباط لموقع Webflow

**إعداد:** Manus AI  
**النطاق:** الموقع التسويقي Webflow فقط. لا تنقل هذه الأدوات بيانات الموظفين أو جلسات HR HBS أو منطق الموافقات إلى Webflow.

> **تنبيه قانوني:** أداة CMP لا تجعل الموقع «متوافقاً مع GDPR» تلقائياً. يجب أن يثبت الفريق الغرض والأساس القانوني والشفافية والاحتفاظ وإدارة الموردين، وأن يراجع مستشار قانوني النصوص والأسواق المستهدفة.

## القرار المختصر

لا توجد أداة واحدة هي الأفضل لكل موقع. لموقع حلول الغد التسويقي، يكون **Cookiebot CMP** خيار البدء العملي عندما تكون الحاجة الأساسية: مسح الكوكيز، حجب غير الضروري قبل الموافقة، بانر ومركز تفضيلات، وربط منظومة Google عند استخدامها. تذكر صفحة التكامل الرسمية في Webflow أن Cookiebot يستطيع مسح الموقع، وحجب الكوكيز غير الضرورية إلى أن يوافق الزائر، وعرض بانر قابل للضبط، وتحديث تصريح الكوكيز بعد المسح. [1]

يكون **OneTrust** الخيار الأنسب إذا كانت الشركة تملك برنامج خصوصية مؤسسياً مركزياً أو مواقع ومناطق تنظيمية متعددة وتحتاج إدارة تفضيلات وموافقات من نفس منظومة الحوكمة. يوضح تكامل Webflow أن تطبيق OneTrust يضم بانرات الموافقة ومركز التفضيلات ويدير الموافقة حسب المناطق والمتطلبات التنظيمية. [2]

يكون **iubenda** خياراً متوازناً عندما تريد الشركة جمع بانر وسياسات خصوصية وكوكيز وسجل موافقة للنموذج ضمن خدمة واحدة. تنص صفحة تكامله مع Webflow على البانرات الجغرافية والحجب المسبق وسجل الموافقات وربط سجلات موافقة النموذج. [3]

| الحالة | التوصية الأساسية | لماذا | ما يجب اختباره قبل الاعتماد |
|---|---|---|---|
| موقع تسويقي واحد مع GA4 أو حملات محدودة | Cookiebot CMP | حجب مسبق ومسح وتصريح كوكيز وتكامل Webflow مباشر | GTM/الوسوم، حركة Webflow، RTL، والنموذج |
| مؤسسة متعددة المواقع أو المناطق ولديها حوكمة خصوصية مركزية | OneTrust | إدارة مركزية للتفضيلات والمناطق والالتزامات | دور الفريق، الترخيص، مسار الاعتماد، وتقارير الحوكمة |
| فريق يحتاج سياسة + بانر + سجل موافقة نموذج في منصة واحدة | iubenda | سياسات مولّدة وبانر وسجل موافقات للنماذج | جودة العربية، سياسة الاحتفاظ، ومسار Zapier/API |
| لا توجد كوكيز غير ضرورية ولا تحليلات أو إعلانات | لا CMP معقدة في البداية؛ راجع سياسة خصوصية شفافة | تقليل الاعتماديات؛ لكن تحقق من كل Script وEmbed | جرد كود كامل قبل اتخاذ القرار |

## طبقات الحل التقني

| الطبقة | الأداة أو الخدمة | الدور | ليست بديلاً عن |
|---|---|---|---|
| إدارة الموافقة | Cookiebot أو OneTrust أو iubenda | بانر، تفضيلات، حجب مسبق، سجل موافقة | سياسة الخصوصية وقرار الأساس القانوني |
| إدارة الوسوم | Google Tag Manager عند تعدد الوسوم | ترتيب تنفيذ الوسوم وربطها بحالات الموافقة | CMP؛ إذ لا يجعل GTM الوسوم واعية بالموافقة وحده [1] |
| التحقق | Google Tag Assistant وأدوات المتصفح | إثبات أن الحالة الافتراضية للموافقة تسبق الوسوم وأن التحديث يحدث بعد اختيار المستخدم | اختبار الخصوصية القانوني أو سجل التغيير |
| النماذج والحقوق | Webflow Forms + CRM/Sandbox + سجل طلبات | استقبال أقل البيانات وإدارة الحذف والتكامل | سجل موافقة الكوكيز |
| الحوكمة | سجل موردين وDPA وسجل تغييرات | مالك ومكان بيانات وغرض وتراجع لكل تكامل | إعداد الأداة التقني فقط |

## مقارنة الاختيار

| معيار القرار | Cookiebot | OneTrust | iubenda |
|---|---|---|---|
| تكامل Webflow مثبت | صفحة تكامل مباشرة وCustom Code/GTM [1] | تطبيق OneTrust في Webflow [2] | صفحة تكامل وCustom Code أو Zapier/API [3] |
| حجب قبل الموافقة | نعم، مع اختبار auto/manual blocking [1] | يدير احترام أدوات التحليل والتسويق لاختيارات المستخدم [2] | نعم، مع prior blocking وتكوين يدوي عند الحاجة [3] |
| سجل موافقة للنموذج | يحتاج تصميم تدفق منفصل بحسب CRM/النموذج | يراجع ضمن برنامج الخصوصية المؤسسي | مسار Consent Database موثق في التكامل [3] |
| سياسات الخصوصية والكوكيز | تصريح كوكيز ديناميكي بعد المسح [1] | يعتمد على حزمة الخصوصية المؤسسية | سياسات خصوصية وكوكيز مولدة وتحديثها من الخدمة [3] |
| ملاءمة الفريق | تسويق/تقنية لموقع واحد أو عدة مواقع خفيفة | خصوصية مؤسسية ومناطق متعددة | فرق تريد حزمة سياسة وموافقة وسجل نموذج |
| الانتباه الخاص | الحجب التلقائي قد يتعارض مع Webflow Interactions؛ اختبر staging [1] | لا تبدأ قبل تأكيد الترخيص والمالك وسياسة المناطق | تحقق من تفاصيل الخطة واللغة ومسار البيانات قبل التعاقد |

## خطة التكامل الموصى بها لموقع حلول الغد

### المسار الافتراضي: Cookiebot CMP

| الخطوة | التنفيذ | معيار القبول |
|---:|---|---|
| 1 | جرد كل cookie وScript وEmbed ووسم تحليل أو إعلان | لا مصدر غير مصنف أو بلا مالك |
| 2 | إعداد Cookiebot للنطاق وإجراء المسح الأول | التصنيف مكتمل للكوكيز غير المصنفة |
| 3 | وضع Script البانر أول عنصر في Head Code أو استخدام GTM عند تعدد الوسوم | لا وسم غير ضروري يعمل قبل الموافقة |
| 4 | إضافة صفحة سياسة كوكيز/تصريح كوكيز ورابط دائم في التذييل | الصفحة تعمل على الهاتف وRTL |
| 5 | ربط كل Tag في GTM بفحص الموافقة؛ لا يفترض أن GTM قام بذلك تلقائياً | Tag Assistant يثبت الحالة الافتراضية والتحديث |
| 6 | اختبار رفض الكل وقبول الإحصاءات وقبول التسويق وتغيير التفضيلات وسحبها | سلوك الوسوم يطابق كل حالة |
| 7 | اختبار Webflow Interactions والنماذج وCTA وRTL بعد الحجب | لا عيب P1 أو تدهور تحويل |

توصي صفحة تكامل Cookiebot باستخدام GTM في المواقع التي لديها عدة Scripts أو حاجة قوية لترتيب التنفيذ، وتؤكد أن كل الوسوم الأخرى تحتاج فحوص موافقة صريحة. [1] إذا أدى الحجب التلقائي إلى تعارض مع Interactions، يستخدم الفريق الحجب اليدوي للوسوم غير الضرورية بدلاً من تعطيل الضوابط.

### المسار المؤسسي: OneTrust

يُعتمد OneTrust عندما يكون القرار جزءاً من برنامج خصوصية أوسع، لا مجرد بانر. يوثق مالك الخصوصية المناطق واللغات والفئات ومالكي النطاقات ومسار مراجعة التغيير، ثم يربط تطبيق OneTrust في Webflow ويختبر أن التحليلات والتسويق يحترمان التفضيلات الإقليمية. [2]

### المسار المتكامل للسياسات والنموذج: iubenda

يُعتمد iubenda عندما تحتاج الشركة إلى الجمع بين سياسة خصوصية وكوكيز، وبانر جغرافي، وحجب مسبق، وسجل للموافقات؛ وتستطيع فرق Webflow ربط موافقة النموذج عبر Custom Code أو مسار Zapier أو API حسب الاعتماد المعتمد. [3] لا ينفذ هذا المسار قبل تحديد أي حقول نموذج وسجل احتفاظ ووجهة بيانات معتمدة.

## اختبارات قبول قبل الإنتاج

| حالة الاختبار | النتيجة المطلوبة | الدليل |
|---|---|---|
| زائر جديد يرفض الكل | لا تحليلات أو إعلانات غير ضرورية تعمل | Network/Tag Assistant وسجل CMP |
| زائر يقبل الإحصاءات فقط | تعمل الإحصاءات فقط ولا يعمل التسويق | Network/Tag Assistant |
| زائر يغير اختياره | تتوقف أو تبدأ الوسوم وفق الخيار الجديد | لقطة وتقرير فني |
| صفحة RTL والهاتف | البانر ومركز التفضيلات واضحان ولا يغطيان CTA دائماً | لقطة وفحص لوحة مفاتيح |
| نموذج طلب عرض | النموذج يعمل بعد كل حالة موافقة ولا ينقل بيانات إلى التحليلات | طلب Sandbox وسجل وجهة |
| Webflow Interactions | لا كسر للحركة أو التنقل بسبب الحجب | اختبار P1 في staging |
| تغيير Script أو مورد | يظهر في الجرد ويخضع لإعادة مسح واختبار | سجل تغيير وموافقة |

## قرار البدء المقترح

1. اعتمد **Cookiebot** لمسار Webflow الأولي إذا كان الموقع التسويقي يملك تحليلات أو إعلانات ويحتاج حجباً قبل الموافقة دون برنامج خصوصية مؤسسي قائم.
2. انتقل إلى **OneTrust** إذا توسعت المنصة إلى مواقع/مناطق متعددة أو احتاجت حوكمة مركزية ومراكز تفضيلات مؤسسية.
3. اختر **iubenda** إذا كانت أولوية الفريق هي الجمع بين السياسات وسجل موافقة النموذج والبنر في منصة واحدة.
4. لا تفعّل أي Script أو GTM أو CMP في الإنتاج قبل اجتياز مصفوفة الاختبار أعلاه واعتماد الخصوصية والتقنية.
