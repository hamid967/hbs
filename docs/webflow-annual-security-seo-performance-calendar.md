# التقويم السنوي للفحص الأمني والصيانة الوقائية وSEO والأداء لموقع Webflow

**إعداد:** Manus AI  
**النطاق:** الموقع التسويقي العام في Webflow، والنماذج والتكاملات والمحتوى والتحليلات المرتبطة به. لا يغطي هذا التقويم تطبيق HR HBS التشغيلي أو بيانات الموظفين والموافقات.

## مبدأ التشغيل

يعامل الموقع بعد الإطلاق كأصل تسويقي متغير، لا كصفحات ثابتة. لذلك يجمع التقويم بين تدقيق التغييرات، ومراقبة التحويل، ومراجعة المحتوى وSEO، وفحص الأداء والإتاحة. توصيات Webflow الرسمية تشمل مراجعة بنية الموقع والاستجابة والتسميات والعناوين ووسوم HTML وmetadata والنص البديل وSSL وSearch Console وsitemap ضمن قائمة SEO المستمرة. [1] وتفيد وثائق Webflow أن سجل نشاط الموقع، عند توفره في خطة المؤسسة، يبين تغييرات الصفحات وCMS والمكونات والكود المخصص والنسخ الاحتياطية والنشر والفاعل الذي نفذ التغيير. [2]

> **قاعدة الحماية:** كل تغيير يمر عبر المعاينة أو staging، ثم تحقق P1، ثم نشر محدود ومراقبة. لا يُمنح Webflow أي وصول إلى جلسات HR HBS أو بيانات الموظفين، ولا تُخزن مفاتيح التكامل داخل الواجهة العامة.

## أفضل ممارسات SEO بعد الإطلاق

ينبغي التعامل مع SEO كدورة صحة مستمرة لا كتغيير مرة واحدة. توصي Webflow بإنشاء URLs قصيرة ووصفية ومتسقة، واستخدام تحويل 301 عندما يتغير الرابط، مع عناوين ووصف meta فريدة لكل صفحة، وإعداد Open Graph على مستوى الصفحة، وتقديم نص بديل وصفي للصور ذات المعنى. [1] يجب أن يمتلك كل عنصر CMS مالكاً وتاريخ مراجعة، مع اختبار أن المحتوى الجديد لا ينتج صفحة بلا عنوان أو وصف أو مسار واضح.

| المجال | ممارسة التنفيذ | اختبار القبول | التكرار |
|---|---|---|---|
| البنية والتنقل | بناء مسارات عربية وصفية وربط الصفحات ذات الصلة بروابط داخلية منطقية | لا صفحة أساسية يتطلب الوصول إليها أكثر من ثلاث نقرات من التنقل المتوقع | ربع سنوي وعند إضافة قسم |
| URLs والتحويلات | تسجيل كل تغيير slug وإنشاء 301 للرابط القديم عند تغييره | لا 404 ناتج عن تغيير URL معتمد | كل تغيير نشر |
| العنوان والوصف | عنوان ووصف فريدان وواضحان لكل صفحة وقالب CMS | 100% من الصفحات الأساسية تملك metadata مكتملة | شهرياً |
| المحتوى | مراجعة الفائدة والدقة والمالك وتاريخ المراجعة قبل النشر | لا مورد أو صفحة حل بلا مالك أو تاريخ مراجعة | شهرياً/ربع سنوي |
| الصور | نص بديل للصور ذات المعنى، واستثناء الصورة الزخرفية | لا صورة سياقية بلا وصف نصي | كل نشر |
| الفهرسة | متابعة sitemap وSearch Console وتغطية الصفحات وتنبيهات الفهرسة | معالجة أسباب الاستبعاد المهمة أو توثيق سببها | شهرياً |
| المشاركة | Open Graph خاص بكل صفحة مهمة | معاينة صحيحة للصفحة عند المشاركة | كل تغيير صفحة |
| القياس | أحداث CTA والنموذج محددة بالاسم والهدف والمصدر من دون بيانات حساسة | 100% من CTA الأساسي يتتبع بشكل صحيح | شهرياً |

## تقنيات الأداء بعد الإطلاق

تصف Google مؤشرات Core Web Vitals بأنها قياس لتجربة المستخدم الفعلية في التحميل والتفاعل والاستقرار البصري، وتقترح استهداف LCP خلال 2.5 ثانية وINP أقل من 200ms وCLS أقل من 0.1؛ كما تشير إلى استخدام تقرير Search Console للمراجعة والتشخيص. [3] تستخدم هذه القيم كأهداف تشغيلية للموقع التسويقي، مع مراعاة أن القياس الميداني أهم من اختبار واحد في بيئة محلية.

| التقنية | الإجراء العملي في Webflow | دليل القياس | التكرار |
|---|---|---|---|
| الصور | تحويل الصور إلى مقاسات مناسبة، ضغطها، وتجنب تحميل صور Hero أكبر من الحاجة | Lighthouse وقياس الصفحة الميداني | عند كل نشر بصري وشهرياً |
| الخطوط | تقليل عائلات وأوزان الخطوط إلى ما يخدم العربية والهوية فقط | طلبات الشبكة وحجم الصفحة | ربع سنوي |
| Scripts الطرف الثالث | جرد tags وchat وanalytics وA/B وإزالة غير المستخدم وتأجيل غير الحرج | قائمة Scripts ونتيجة Lighthouse | شهرياً وبعد حملة |
| الاستقرار البصري | إعطاء وسائط المحتوى مساحة ثابتة وتجنب إدخال عناصر متأخرة فوق المحتوى | CLS في Search Console ولighthouse | شهرياً |
| التفاعل | تخفيف الكود المخصص الثقيل وتجنب ربط إجراءات كثيرة بالتمرير | INP ميداني واختبار جهاز هاتف | شهرياً |
| القوالب وCMS | مراجعة أن صفحات المورد والميزة لا تحمل مكونات لا تستخدمها | تقرير طلبات الشبكة وحجم DOM | ربع سنوي |
| الهاتف | أولوية اختبار الهاتف على الشبكة المعتادة وRTL والنموذج | رحلة P1 حية في staging | كل إصدار |

## بوابة التغيير الآمن

قبل أي تغيير كبير في المحتوى أو القالب أو الكود أو النماذج، يجب ربط التغيير بمالك وهدف ونطاق، وإجراء المعاينة أو staging، وتشغيل حالات P1، وتسجيل النتيجة، ثم النشر خلال نافذة مراقبة مع خطة تراجع. إذا كانت خطة Webflow لا توفر سجل النشاط، يستخدم الفريق سجل تغيير خارجي يوضح الفاعل والتاريخ والصفحات المتأثرة وحالة النشر؛ أما إذا كان سجل النشاط متاحاً، فيستفاد من مرشحات التغييرات وحالة staging والإنتاج للتحقق من التغيير.
