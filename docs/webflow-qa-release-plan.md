# خطة الاختبار وضمان الجودة لموقع Webflow قبل الإطلاق

## الغرض وحدود الجودة

تهدف هذه الخطة إلى التأكد من أن موقع حلول الغد التسويقي على Webflow واضح وسريع ومتوافق مع الأجهزة وسليم التحويل، من دون خلطه بتطبيق HR HBS التشغيلي. لا يشمل نطاق QA هذا التحقق من طلبات الموظفين أو الموافقات أو بيانات الشركات؛ تلك تبقى داخل التطبيق الداخلي وضمن خطط اختبار وصلاحيات مستقلة.

| داخل نطاق QA لموقع Webflow | خارج النطاق |
|---|---|
| الصفحات العامة والتنقل والمحتوى وCMS | سير الموافقات أو بيانات الموظفين في HR HBS |
| نماذج طلب العرض والتحويلات والتكامل المعتمد | مشاركة جلسات الدخول أو مفاتيح الخدمات مع Webflow |
| RTL، الهاتف، الإتاحة، SEO الأساسي، الأداء | الاستشارات القانونية أو وعود تسويقية غير معتمدة |
| أحداث التحليلات وملفات تعريف الارتباط المصرح بها | إدخال بيانات شخصية حقيقية للاختبار دون موافقة |

## الأدوار وبيئات الاختبار

| الدور | المسؤولية | بيئة العمل |
|---|---|---|
| مالك المنتج | اعتماد النطاق وبوابة الإطلاق | نسخة المعاينة وبيئة الإنتاج |
| التسويق | دقة الرسائل وCTA والمحتوى وUTM | نسخة محتوى/معاينة |
| محرر CMS | اكتمال المجموعات والتصنيفات وتاريخ المراجعة | نسخة CMS اختبارية |
| الجودة | تنفيذ السيناريوهات وتسجيل العيوب وإعادة الفحص | معاينة Webflow وبيئة اختبار التكامل |
| التقنية | النماذج وWebhook والتحليلات وسياسة الخصوصية | نقطة خلفية أو CRM Sandbox عند توفره |
| الأمن والخصوصية | مراجعة الحقول والموافقة وعدم تسرب البيانات | مراجعة قبل بوابة الإنتاج |

| البيئة | الاستخدام | متطلبات الدخول |
|---|---|---|
| Webflow Preview أو Staging | التحقق الوظيفي والمحتوى والاستجابة | محتوى اختبار معتمد وغير شخصي |
| CRM Sandbox أو وجهة Webhook اختبارية | اختبار الإرسال والتعامل مع الخطأ | مفاتيح اختبار فقط محفوظة خارج الواجهة |
| الإنتاج | التحقق بعد الإطلاق فقط | لا اختبار يسبب طلبات مبيعات حقيقية دون وسم واضح |

## معايير الدخول والخروج

| بوابة الدخول للاختبار | بوابة الإطلاق النهائي |
|---|---|
| اعتماد خريطة الصفحات وCTA والنطاق | لا عيوب حرجة أو عالية مفتوحة |
| اكتمال نسخة المحتوى أو وضع وسم واضح للمحتوى المؤجل | جميع سيناريوهات P1 ناجحة |
| تحديد وجهة نموذج طلب العرض ومالك البيانات | نموذج الطلب وتحليلات التحويل مثبتان في الإنتاج |
| تجميد تغييرات النطاق أثناء دورة QA | اعتماد المنتج والتسويق والتقنية والأمن |
| توفر بيئة معاينة ومتصفحات اختبار | وجود خطة مراقبة وتراجع بعد الإطلاق |

## مصفوفة حالات الاختبار

| المجال | سيناريو الاختبار | النتيجة المقبولة | الأولوية | الدليل |
|---|---|---|---|---|
| التنقل | فتح كل عنصر رأس وتذييل ومسار CTA | الصفحة المقصودة صحيحة ولا توجد روابط مكسورة | P1 | سجل روابط/لقطات |
| RTL | مراجعة اتجاه النص والأرقام والمحاذاة على كل قالب | لا انقلاب في ترتيب الواجهة أو قص للنص | P1 | لقطة هاتف وسطح مكتب |
| الاستجابة | الرئيسية والحلول والمورد وطلب العرض على هاتف/لوحي/سطح مكتب | لا تداخل أو تمرير أفقي غير مقصود | P1 | مصفوفة أجهزة |
| CMS | نشر مسودة اختبار وتحديثها وإخفاؤها | القالب يعرض البيانات الصحيحة وتعمل حالات الفراغ | P1 | سجل CMS |
| CTA | اختبار كل CTA رئيسي وثانوي | وجهة صحيحة ووسم UTM سليم عند استخدامه | P1 | جدول تتبع |
| نموذج العرض | حقول صحيحة، تحقق، نجاح، خطأ، ومنع إرسال ناقص | رسالة مفهومة وإرسال واحد فقط للبيانات الصالحة | P1 | لقطة وطلب اختبار |
| تكامل النموذج | تسليم طلب اختبار إلى CRM/Webhook المتفق | الحمولة كاملة والوجهة الصحيحة بلا تكرار | P1 | سجل Sandbox |
| الخصوصية | مراجعة الحقول والموافقة والروابط القانونية | يجمع الحد الأدنى من البيانات وبموافقة واضحة | P1 | مراجعة الخصوصية |
| الإتاحة | تنقل لوحة المفاتيح، التركيز، العناوين، النص البديل | جميع العناصر التفاعلية قابلة للوصول وواضحة | P1 | قائمة فحص |
| الأداء | اختبار الصفحات الأساسية على شبكة هاتف معتادة | ضمن ميزانية الأداء المعتمدة؛ لا صور ثقيلة غير مبررة | P2 | تقرير أداء |
| SEO | عنوان ووصف ورابط أساسي وOpen Graph وفهرسة مناسبة | لا عناوين مكررة أو صفحة عامة بلا بيانات أساسية | P2 | جدول metadata |
| التحليلات | CTA وإرسال النموذج ونجاحه مسجلان بأحداث معرفة | الحدث يحمل الاسم والمصدر والهدف دون بيانات حساسة | P1 | لقطة Debug/سجل حدث |
| الحدود مع HR HBS | CTA إلى التطبيق أو الدخول | تحويل فقط؛ لا مشاركة جلسة أو كشف بيانات تشغيلية | P1 | مراجعة تقنية |

## الإتاحة وSEO والأداء

| المحور | معيار القبول | فشل يوقف الإطلاق |
|---|---|---|
| لوحة المفاتيح | انتقال منطقي وfocus ظاهر لكل عنصر تفاعلي | لا يمكن إرسال النموذج أو فتح القائمة بلوحة المفاتيح |
| النصوص البديلة | صور المحتوى ذات وصف مناسب والصور الزخرفية مستثناة | صورة تحمل معنى بلا بديل نصي |
| التباين | النص وCTA واضحان في الحالة العادية والتركيز | CTA أو نص أساسي غير مقروء |
| العناوين والهيكل | H1 واحد وتسلسل عناوين منطقي لكل صفحة | هيكل يمنع فهم الصفحة أو التنقل فيها |
| بيانات البحث | عنوان ووصف ورابط أساسي لكل قالب | صفحة تسويقية أساسية بلا metadata |
| الحجم والأداء | صور مضغوطة، خطوط لازمة فقط، وسائط مؤجلة عند اللزوم | مورد يمنع تحميل المحتوى أو النموذج |

## تسلسل تنفيذ QA

| اليوم | المخرج | بوابة القرار |
|---:|---|---|
| 1 | تدقيق المحتوى والبنية وCMS والروابط | تجميد النطاق في دورة QA |
| 2 | اختبار RTL والاستجابة والمتصفحات | لا عوائق P1 في الهاتف أو التنقل |
| 3 | اختبار النموذج والتكامل والخصوصية والتحليلات | نجاح طلب اختبار في الوجهة المعتمدة |
| 4 | اختبار الإتاحة وSEO والأداء وإصلاح العيوب | إغلاق الحرجة والعالية |
| 5 | إعادة اختبار وبوابة الإطلاق وخطة المراقبة | اعتماد الأطراف الأربعة |

## بوابة الإطلاق وخطة التراجع

يوقع مالك المنتج والتسويق والتقنية والأمن على بوابة الإطلاق بعد تأكيد جميع سيناريوهات P1 وعدم وجود عيوب حرجة أو عالية. بعد النشر، تراقب جهة النموذج والتحليلات و404 والأداء خلال أول 24 ساعة. إذا تعطّل نموذج طلب العرض، أو ظهر تسرب بيانات، أو فشلت الصفحة الرئيسية أو مسار التحويل، يعود الفريق إلى النسخة المنشورة السابقة أو يعطّل التكامل المتأثر وفق خطة التراجع المعتمدة، ثم يوثق الحادث قبل إعادة النشر.
