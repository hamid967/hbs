# خطة الصيانة والتحديثات الدورية لموقع Webflow بعد الإطلاق

## هدف التشغيل

تهدف الخطة إلى إبقاء الموقع التسويقي موثوقاً، متوافقاً مع هوية حلول الغد، صالحاً للتحويل، وسهل التحرير من دون التأثير في تطبيق HR HBS الداخلي. تعتمد الخطة مبدأ **النشر إلى بيئة staging ثم المراجعة ثم الإنتاج**؛ وهي ممارسة تتسق مع إرشادات Webflow للنشر المرحلي [1].

| المجال | هدف الصيانة | المالك |
|---|---|---|
| المحتوى وCMS | دقة الرسائل وتاريخ مراجعة لكل أصل محتوى | التسويق ومحرر CMS |
| التحويلات | صحة CTA والنماذج ووصول الطلب إلى وجهته | التسويق والتقنية |
| الجودة التقنية | أداء وإتاحة وSEO وروابط سليمة | الجودة والتقنية |
| الحوكمة | أثر واضح لكل تغيير وموافقة قبل الإنتاج | مالك المنتج |
| الأمن والخصوصية | حقول محدودة وصلاحيات تحرير متناسبة وعدم كشف مفاتيح | الأمن والتقنية |

## إيقاع الصيانة

| الإيقاع | أعمال الصيانة | معيار الإغلاق |
|---|---|---|
| يومي في أول 14 يوماً | مراقبة نموذج العرض و404 وأحداث التحويل والملاحظات الحرجة | كل مشكلة P1 تملك مالكاً وقراراً |
| أسبوعي | مراجعة طلبات المحتوى، الروابط، CTA، النموذج، وإصدار staging | تقرير جودة مختصر ونتيجة النشر |
| شهري | مراجعة CMS وSEO والأداء والإتاحة وسجل التغييرات | سجل تحسينات بمواعيد وملاك |
| ربع سنوي | مراجعة الرسائل والتكاملات والصلاحيات وخطة التحسين | اعتماد مالك المنتج والأمن والتسويق |
| عند حادث | عزل الأثر، إصلاح أو تراجع، تحليل سبب جذري | محضر حادث وإجراء يمنع التكرار |

## مسار التغيير والنشر

| الخطوة | الإجراء | الدليل |
|---:|---|---|
| 1 | فتح طلب تغيير يحدد الصفحة والهدف والأثر والمالك | بطاقة تغيير |
| 2 | تحرير المحتوى أو التصميم في نسخة عمل خاضعة للمراجعة | رابط المعاينة |
| 3 | نشر إلى staging وتنفيذ قائمة QA الملائمة للتغيير | نتائج الاختبار |
| 4 | مراجعة التسويق والمنتج؛ مراجعة التقنية والأمن عند وجود نموذج أو تكامل | موافقات مسجلة |
| 5 | نشر إلى الإنتاج في نافذة متفق عليها | سجل إصدار |
| 6 | مراقبة التحويل و404 والنموذج خلال أول 24 ساعة | تقرير ما بعد النشر |

## قائمة صيانة المحتوى وCMS

| الفحص | الإجراء | التكرار |
|---|---|---|
| ملكية المحتوى | كل صفحة ومورد وقصة حالة لها مالك وتاريخ مراجعة | شهري |
| الدقة | مراجعة العناوين والميزات وCTA وروابط السياسات | شهري وعند تغيير المنتج |
| عدم الادعاءات غير المدعمة | منع شهادات أو نتائج أو وعود بلا موافقة ودليل | قبل كل نشر |
| سلامة القوالب | اختبار حالة منشور ومسودة وفارغ لمجموعات CMS | عند تعديل القالب |
| الأرشفة | إيقاف المحتوى المنتهي أو وضع تاريخ مراجعة جديد | ربع سنوي |

## الأمن والخصوصية والتكاملات

لا يحوي Webflow منطق تطبيق HR HBS أو بيانات الموظفين أو جلسات المستخدمين. تخضع نماذج التحويل لمبدأ الحد الأدنى من الحقول، وتصل إلى CRM أو خدمة خلفية عبر وجهة اختبار/إنتاج منفصلة. تستخدم Webflow أحداث webhook لإشعارات إرسال النماذج، وتوصي وثائقها بالتحقق من توقيع الطلب في المستلم [2].

| الضبط | الإجراء | التكرار |
|---|---|---|
| صلاحيات المحررين | مراجعة الأعضاء والأدوار وإزالة الوصول غير الضروري | ربع سنوي وعند المغادرة |
| مفاتيح التكامل | حفظها في بيئة الخادم أو الموفر، لا في الصفحة أو JavaScript العام | عند كل تغيير |
| نموذج العرض | اختبار الحقول والموافقة والنجاح والفشل وتسليم الحمولة | أسبوعي وأي تغيير |
| سجل التغييرات | مراجعة من غيّر ماذا ومتى والرجوع عند الحاجة | شهري أو بعد حادث |
| خصوصية المحتوى | فحص عدم رفع بيانات عملاء أو موظفين أو أسرار في CMS | قبل النشر |

## مؤشرات صحة ما بعد الإطلاق

| KPI | الهدف | حد التنبيه | المالك |
|---|---:|---:|---|
| نجاح نموذج طلب العرض | 100% لعينات الاختبار | أقل من 100% | التقنية + التسويق |
| صحة روابط وCTA | 100% في قائمة QA | أقل من 100% | الجودة |
| عيوب حرجة مفتوحة | 0 | أكثر من 0 | مالك المنتج |
| صفحات CMS ذات تاريخ مراجعة سليم | 100% | أقل من 95% | محرر CMS |
| نجاح فحوص Lighthouse الأساسية | 100% ضمن ميزانية الفريق | أي انحدار متفق عليه | الجودة + التقنية |
| انتهاكات الإتاحة الآلية الحرجة | 0 | أكثر من 0 | التصميم + الجودة |
| التغييرات دون طلب/موافقة | 0 | أكثر من 0 | مالك المنتج |

## الاستجابة للحوادث والتراجع

| الحالة | الاستجابة خلال | الإجراء الأول | قرار التراجع |
|---|---|---|---|
| نموذج معطّل أو بيانات لا تصل | ساعة عمل | تعطيل CTA المتأثر أو توجيهه لمسار بديل معتمد | التراجع إذا لم يصلح التكامل سريعاً |
| صفحة رئيسية أو CTA مكسور | ساعة عمل | تحديد الإصدار وتطبيق إصلاح أو نشر نسخة سابقة | تراجع إذا أثر على التحويل الرئيسي |
| كشف محتوى أو بيانات غير مناسبة | فوري | إلغاء النشر أو حذف المحتوى وتقييد الوصول | مراجعة أمنية قبل إعادة النشر |
| انحدار أداء أو إتاحة | يوم عمل | تحديد المورد أو المكون المتأثر وإصلاحه في staging | لا تراجع إلا إذا منع الوصول أو التحويل |
