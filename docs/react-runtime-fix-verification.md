# تحقق إصلاح React وDropdownMenu

## التشخيص

سجل المتصفح أظهر `Invalid hook call` وقراءة `useMemo` من dispatcher فارغ داخل Radix DropdownMenu. أظهر فحص الاعتمادات React وReact DOM بالإصدار 19.2.1، لكن مزيج مكوّنات Radix مع ملفات Vite المحسنة يؤشر إلى حل React مختلف أو ذاكرة prebundle قديمة في بيئة التطوير.

## الإصلاح

يفرض إعداد Vite توحيد `react` و`react-dom` عبر `resolve.dedupe`، ويعيد بناء prebundle لمكتبات React وDropdownMenu. أضيف اختبار يتحقق من عقد الإعداد، ونُظفت ذاكرة Vite المحلية قبل بدء نسخة التحقق.

## المعاينة

بدأ خادم فرع الإصلاح على المنفذ 3104 وفتح `/app` دون ظهور خطأ Hook قبل إعادة التوجيه إلى بوابة OAuth. لم تُنفذ مصادقة أو تغييرات بيانات، لذا لا يثبت هذا الفحص سلوك القائمة المنسدلة داخل جلسة مستخدم حقيقية. يثبت أن نسخة الإصلاح تحمل مسار التطبيق وتصل إلى بوابة الدخول من دون تكرار الخطأ قبل المصادقة.

## حالة فحوص PR

نجحت فحوص النوع والاختبارات والبناء محلياً، كما نجح فحص `HBS Verification` ومعاينات النشر في PR #26. بقي فحص `Deno/test` فاشلاً لأنه يشغّل linter Deno على مشروع Node/TypeScript كامل ويبلغ عن 225 مشكلة قائمة في ملفات غير معدلة، منها استعمال `process` و`any` في طبقة الخادم. هذا قيد CI موجود خارج نطاق إصلاح React ولا يمثل فشل اختبار DropdownMenu؛ يجب ضبط workflow Deno أو نطاقه في PR بنية تحتية مستقل.
