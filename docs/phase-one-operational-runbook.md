# دليل تشغيل المرحلة الأولى

## الهدف

تثبت المرحلة الأولى أساس الجودة والإتاحة والحوكمة للتطبيق القائم. لا تتضمن هذه المرحلة محرك رواتب أو تخزين مستندات أو تكاملات حكومية أو تشغيل وكلاء ذاتيين.

## فحص الجودة الموحد

قبل حفظ أي دفعة للمرحلة الأولى، شغّل الأمر التالي من جذر المشروع:

```bash
pnpm quality:phase1
```

يشغّل الأمر فحص TypeScript واختبارات Vitest وبناء الإنتاج بالتتابع. أي فشل يوقف الدفعة قبل الحفظ، ويُعالج في الفرع أو الدفعة نفسها قبل إصدار نقطة استعادة جديدة.

## حدود التشغيل

| المجال | الحد الحالي |
|---|---|
| نقاط الاستعادة | تعرض اللوحة نقطة استعادة مرجعية وتسمح بطلب تراجع مؤكد؛ لا تنفذ الواجهة تراجعاً أو نشراً تلقائياً. |
| الاعتماديات المحجوبة | يسجل المسؤول طلب مراجعة ثم إقرار حل الاعتمادية ثم طلب إعادة محاولة؛ لا تنشئ هذه الخطوات اتصالاً خارجياً. |
| الرواتب والمالية | غير داخل النطاق حتى اعتماد مزود ونطاق محاسبي وبيئة اختبار ومراجعة بشرية. |
| الوثائق والتوقيع | غير داخل النطاق حتى اعتماد تصنيف المستندات والاحتفاظ والتوقيع والتخزين الآمن. |
| التكاملات الحكومية | لا تكامل حي دون API رسمي ومفاتيح اختبار وموافقة المالك. |
| القبول الحي | تتطلب مراحل الموافقات والأمن والقبول جلسات OAuth مستقلة للأدوار المطلوبة؛ لا تغلق باختبارات آلية فقط. |

## الإتاحة

تتضمن لوحة التنفيذ إعلاناً نصياً مخفياً لقارئات الشاشة يوضح ملخص حالة المراحل ومراجعات الاعتماديات في الشركة الحالية. تستمر النوافذ المنبثقة عبر مكونات Radix في دعم التركيز وإغلاق النافذة، مع وجود نص صريح لكل إجراء حساس.

## قرار الإغلاق

تُحفظ الدفعة فقط بعد نجاح `quality:phase1` ومراجعة الواجهة المرئية. لا يُنقل بند مالي أو حكومي أو حي إلى مكتمل إلا عند استيفاء بوابته التشغيلية الموثقة.
