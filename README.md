# حلول الغد | HR HBS

منصة عربية متكاملة لإدارة طلبات **الموارد البشرية** و**العلاقات الحكومية**، مع مسارات موافقات متعددة المراحل، وإدارة موظفين وصلاحيات، وتقارير تشغيلية شهرية قابلة للتصدير. صُممت الواجهة باتجاه من اليمين إلى اليسار، وتدعم عزل البيانات حسب الشركة ونطاق عمل المدير المباشر.

> **حالة المشروع:** تطبيق Full-Stack يعمل محلياً ومنشور عبر بيئة الاستضافة المُدارة. الربط مع GitHub مهيأ محلياً على المستودع `hamid967/hbs`، من دون دفع ملفات إلى المستودع البعيد الفارغ حتى يُطلب ذلك صراحة.

## لمحة عن القدرات

| المجال | ما يتضمنه الإصدار الحالي |
|---|---|
| الحسابات والصلاحيات | دخول موحد، حسابات معلّقة حتى التفعيل الإداري، أدوار، وحدات وصول، وقوالب صلاحيات للشركة. |
| الموظفون | دليل موظفين وأقسام، مدير مباشر، ومنطقة جغرافية لتغذية التصفية التشغيلية. |
| الطلبات | تقديم طلبات الموارد البشرية والعلاقات الحكومية، مع سجل حالة وتفاصيل لكل طلب. |
| الموافقات | مرحلة مدير مباشر، ثم إحالة تلقائية إلى الموارد البشرية أو العلاقات الحكومية، مع إشعارات وسجل مراحل محمي. |
| الإجازات والمصروفات | إجازات سنوية ومرضية وطارئة، ومصروفات سفر وتشغيل بالريال السعودي. |
| التقارير | تقارير شهرية حسب الشركة أو فريق المدير، مقارنة شهرية، اتجاهات زمنية، تصفيات فئة ومنطقة، وتصدير Excel وPDF. |
| تجربة المنتج | صفحة تسويقية عربية بإنترو متحرك، مؤشرات حية، رسوم اتجاه، ونوافذ تفصيلية تفاعلية. |

## البنية التقنية

| الطبقة | التقنية المستخدمة | المسؤولية |
|---|---|---|
| الواجهة | React 19، TypeScript، Wouter، Tailwind CSS 4، Radix UI | واجهة RTL متجاوبة، نماذج، لوحات، رسوم ومؤشرات. |
| واجهة البيانات | tRPC 11 وTanStack Query | عقود API مصنفة بين العميل والخادم من دون REST يدوي. |
| الخادم | Express 4 وNode.js | جلسات الدخول، إجراءات tRPC، وسياسات الوصول. |
| البيانات | MySQL/TiDB، Drizzle ORM | الشركات، المستخدمون، الموظفون، الطلبات، الموافقات، الإشعارات والتقارير. |
| المصادقة | Manus OAuth | دخول موحد وجلسات خادمية؛ لا توجد كلمات مرور محلية في التطبيق. |
| الاختبارات | Vitest | اختبارات وحدة وتكامل للصلاحيات، الموافقات، التقارير والتصدير. |

## مسارات الصلاحيات والموافقات

تظل جميع استعلامات الأعمال ضمن `companyId` للمستخدم. لا يعتمد العزل على إخفاء عناصر الواجهة فقط؛ بل يُفرض في طبقة البيانات وإجراءات الخادم.

| الدور | النطاق التشغيلي |
|---|---|
| مسؤول الشركة أو الموارد البشرية | عرض تقارير الشركة كاملة، إدارة الموظفين والقوالب، ومراجعة مهام الوحدة المخولة. |
| المدير | عرض فريقه المباشر فقط، واستقبال مهام المرحلة الأولى المعينة له. |
| الموظف | إنشاء طلباته ورؤية حالاتها وتواريخ المراحل دون ملاحظات المراجعين التفصيلية. |
| العلاقات الحكومية | مراجعة المرحلة الثانية للطلبات التابعة لوحدة العلاقات الحكومية فقط. |

ينشئ كل طلب مهمة للمدير المباشر أولاً. عند غياب مدير محدد، يعيّن النظام مسؤولاً نشطاً من الشركة بصفة مؤقتة ويظهر تنبيه تشغيلي. بعد قرار المدير بالموافقة، ينتقل طلب الموارد البشرية إلى وحدة HR وطلب العلاقات الحكومية إلى وحدتها تلقائياً. عند الحسم، يتلقى الموظف إشعاراً بالقرار.

## مركز التقارير

يعرض مركز التقارير الإجازات والمصروفات ضمن الشهر المختار، مع فرق ونسبة تغير آمنة مقارنة بالشهر السابق. يستطيع المسؤول والموارد البشرية الوصول إلى نطاق الشركة، بينما يرى المدير نطاق فريقه المباشر فقط.

تشمل واجهة التحليل بطاقات قابلة للنقر، ورسوم Sparklines، ورسوماً موسعة داخل نافذة تفصيلية. تدعم النافذة تحديد شهر البداية والنهاية، وتصفيات الفئات والمناطق، وتلميحات تفاعلية لنقاط البيانات، ومقارنة الشهر الحالي بالشهر السابق أو بثلاثة أشهر سابقة. عند غياب مرجع صالح، تعرض الواجهة حالة صريحة بدلاً من نسبة مضللة.

### تصدير التقارير

يمكن تصدير نتائج التقرير الحالية إلى:

| التنسيق | المحتوى |
|---|---|
| Excel (`.xlsx`) | ملخص الإجازات حسب النوع، المصروفات حسب النوع، والقيم والمقارنات الزمنية. |
| PDF (`.pdf`) | ملخص تشغيلي قابل للمشاركة مبني على نطاق التقرير المصرح به. |

## التشغيل المحلي

### المتطلبات

يلزم Node.js 22 أو أحدث، و`pnpm`، وقاعدة MySQL أو TiDB متوافقة. تستخدم بيئة الاستضافة متغيرات دخول وقاعدة بيانات مُدارة؛ لا تُنشئ أو ترفع ملف `.env` إلى المستودع.

### الأوامر

```bash
# تثبيت الاعتمادات
pnpm install

# تشغيل الخادم وواجهة التطوير
pnpm dev

# فحص TypeScript دون إنتاج ملفات
pnpm check

# تشغيل اختبارات Vitest
pnpm test

# بناء تطبيق الإنتاج
pnpm build

# تشغيل حزمة الإنتاج بعد البناء
pnpm start
```

### قاعدة البيانات والترحيلات

يحفظ مخطط Drizzle في `drizzle/schema.ts` وتوجد ملفات الترحيل في `drizzle/`. عند تعديل المخطط، راجع الترحيل المُولد ثم طبقه في قاعدة البيانات عبر المسار التشغيلي المعتمد؛ لا تطبق ترحيلات غير مُراجعة على بيئة تحتوي بيانات حية.

```bash
# توليد ترحيل Drizzle محلياً عند تغيير المخطط
pnpm drizzle-kit generate
```

## متغيرات البيئة

يوضح الجدول التالي أسماء المتغيرات الأساسية فقط. تحفظ قيمها في بيئة الاستضافة أو في مخزن أسرار آمن، ولا يجب تضمينها في README أو Git.

| المتغير | الغرض |
|---|---|
| `DATABASE_URL` | اتصال MySQL/TiDB. |
| `JWT_SECRET` | توقيع جلسات الدخول. |
| `VITE_APP_ID` | معرّف تطبيق OAuth. |
| `OAUTH_SERVER_URL` | عنوان خدمة OAuth. |
| `VITE_OAUTH_PORTAL_URL` | بوابة تسجيل الدخول في الواجهة. |
| `HRHBS_ADMIN_EMAIL` | بريد المسؤول المعتمد، يُستخدم على الخادم فقط. |
